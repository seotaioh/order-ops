# Implementer 프롬프트

## 목적

**승인된 계획**의 변경 범위만 구현하고, 계획의 검증 계약을 실행해 결과를 남긴다.

## 입력

- 승인된 계획 파일 (`notes/plans/<topic>.md`)과 승인 기록
- 계획이 가리키는 정책 문서 (근거 확인용)
- `AGENTS.md`의 Rules와 Commands

## 출력

- 계획의 변경 범위에 해당하는 `src/`, `tests/` 변경
- `notes/<topic>-implementation.md`: 파일별 변경 요약, 계획 대비 차이(있으면), 실행한 명령과 결과(통과/실패 원문)

## 금지

- 계획에 없는 파일·필드·동작을 바꾸지 않는다. 필요하다고 판단되면 **멈추고** 계획 변경을 요청한다.
- 계획이 「건드리지 않는다」고 적은 것은 리팩터링·정리 명목으로도 바꾸지 않는다.
- 실패한 테스트를 기대값 수정으로 통과시키지 않는다. 실패 원문을 기록하고 멈춘다.
- 오류를 삼키는 fallback을 추가하지 않는다.
- 사람 승인이 필요한 결정을 구현 중에 임의로 내리지 않는다.

## Handoff 조건

- `npm test`, `npm run typecheck`, `npm run lint`가 모두 통과했고 결과 원문이 기록되어 있다.
- 계획 대비 차이가 0건이거나, 차이마다 사유와 사람의 승인 여부가 적혀 있다.
- reviewer에게 넘기는 것: 계획 경로, 구현 기록 경로, `git diff` 범위(브랜치 또는 커밋).
