# 테스트 보강 프롬프트

새 기능을 만드는 프롬프트가 아니다. 현재 동작과 정책에서 **테스트가 잡지 못하는 케이스**를 찾고, 상태 변화·응답·저장 결과를 실제로 판정하는 assertion을 추가한다. 테스트 개수는 성과가 아니다. 사람이 「테스트 보강이 필요하다」고 판단한 뒤 아래 빈칸을 채워 준다. 자동으로 실행되지 않는다.

## 입력

| 항목 | 값 |
| --- | --- |
| 대상 코드 | `src/______` (읽기 전용) |
| 적용 정책 | `AGENTS.md` Policy Routing이 가리키는 문서와 절: `docs/______-policy.md` 「______」 |
| 기존 테스트 | `tests/______` (현재 `tests/orders.test.ts` 한 파일. 어떤 describe·it이 이미 무엇을 단언하는지 먼저 읽는다) |
| 승인된 계획 또는 Issue | `notes/plans/______.md` 또는 Issue #`____` (있으면 그 Acceptance Criteria가 시나리오의 기준) |
| 검증 명령 | `npm test` → `npm run typecheck` → `npm run lint` |
| 구현 변경 허용 여부 | 사람이 적는다: `테스트만` / `구현도` / `미정(멈추고 질문)` |

네 입력(코드·정책·기존 테스트·검증 명령)이 모두 없으면 시작하지 않고 빠진 것을 묻는다.

## 금지

- 테스트 개수 늘리기, 커버리지 숫자, 통과만 하는 assertion(`toBeDefined()`, 「200이 아님」 같은 느슨한 검사)을 목표로 삼지 않는다. 정책이 정확값을 적어 둔 응답은 정확값으로 단언한다.
- 새 기능이나 요청에 없는 동작을 테스트로 먼저 만들어 구현을 끌어내지 않는다.
- 테스트가 실패했을 때 기대값을 현재 코드에 맞춰 고치지 않는다. 정책 문장과 코드가 다르면 그것이 발견이며, 멈추고 보고한다(`AGENTS.md` Rules).
- 「구현 변경 허용 여부」가 `테스트만`이거나 `미정`이면 `src/`를 수정하지 않는다. 구현을 고쳐야만 통과하는 케이스는 보고하고 사람이 정하기 전에는 손대지 않는다.
- 오류를 삼키는 fallback을 테스트나 구현에 넣지 않는다.
- 테스트 입력·고정값·주석에 실제 카드 번호, 토큰, 키, 고객 식별 정보를 쓰지 않는다. 기존 `CARD-…`/`FAIL-…` 같은 모사 토큰만 쓴다.

## 출력

1. **빠진 케이스 표** — 정책 문장 ↔ 현재 테스트 ↔ 공백

   | 정책 문장(문서·절 인용) | 관련 코드 | 현재 테스트(이름) | 공백(무엇을 단언하지 않는가) |
   | --- | --- | --- | --- |

2. **추가·수정할 테스트** — 케이스마다

   | 테스트 이름 | 준비 조건 | 행동 | 단언이 확인하는 것: 상태 변화 / 응답 / 저장 결과 중 어느 것, 기대 정확값 | 근거 정책 문장 |
   | --- | --- | --- | --- | --- |

   한 테스트가 상태·응답·저장 결과 중 무엇을 확인하는지 드러나야 한다. 세 가지를 모두 검사해도 되지만 항목별로 어떤 단언인지 적는다.

3. **구현 변경이 필요한 케이스** — 테스트만으로 통과할 수 없는 것. 「왜 구현이 달라야 하는가」와 정책 근거를 적고, 사람이 결정하기 전에는 구현하지 않는다. 없으면 `없음`.

4. **적용 범위** — 바꾼 파일은 `tests/` 아래 어느 파일인지, `src/`는 바꾸지 않았는지.

## 검증

- `npm test`, `npm run typecheck`, `npm run lint`를 순서대로 실행하고 결과 원문(통과 개수, 실패 메시지 첫 줄)을 남긴다. 실행하지 못한 명령은 「미실행」과 사유를 적는다.
- 새 단언이 실제로 회귀를 잡는지 확인한다: 가능하면 대상 코드의 해당 분기를 임시로 바꿨을 때 **새 테스트만** 실패하는지 본 뒤 되돌린다(별도 worktree 권장, 원래 트리 `src/` diff 없음 확인).
- 출력 1의 공백 중 출력 2로 덮이지 않은 것이 있으면 이유를 적는다(정책 미확정, 사람 결정 대기 등).
- `git diff --name-only`가 `tests/`(와 허용된 경우 `src/`)만 포함하는지 확인한다.
- 사람에게 돌려주는 것: 빠진 케이스 표, 추가한 테스트 목록, 구현 변경 필요 케이스, 검증 결과 원문. 다음 수정으로 넘어갈지는 사람이 정한다.
