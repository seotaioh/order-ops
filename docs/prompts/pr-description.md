# PR 설명 프롬프트

diff와 **실제로 실행한** 검증 결과만으로 PR 설명을 쓴다. 그럴듯한 요약보다 확인된 변경과 검증 사실을 정확히 전달하는 것이 목적이다. 실행하지 않은 검증을 통과했다고 쓰지 못하게 하는 경계가 이 계약의 핵심이다. 사람이 PR을 열기 직전에 빈칸을 채워 준다.

## 입력

| 항목 | 값 |
| --- | --- |
| diff 범위 | `git diff <base>..<head>` — base `______`, head `______` (브랜치 또는 커밋) |
| 변경 파일 목록 | `git diff --name-only <base>..<head>` 출력 |
| 요청 원문 | Issue #`____` 또는 `notes/______-request.md` (Acceptance Criteria가 있으면 그 항목별로 증거를 붙인다) |
| 승인된 계획 | `notes/plans/______.md` (있으면) |
| 실행한 검증 결과 원문 | `npm test` / `npm run typecheck` / `npm run lint` 및 그 밖의 명령의 출력 원문(통과 개수, 실패 메시지). 실행한 사람·시각·커밋 |
| 실행하지 않은 검증 | 명령 이름과 미실행 사유 |

diff와 실행한 검증 결과 원문이 없으면 시작하지 않는다. 「아마 통과할 것」은 입력이 아니다.

## 금지

- 실행하지 않은 검증을 통과했다고 쓰지 않는다. 출력 원문이 입력에 없는 명령은 「실행하지 않음」으로만 적는다.
- 불확실한 내용을 사실처럼 단정하지 않는다. 확인하지 못한 것은 「미확인」으로 표시한다.
- diff에 없는 변경을 설명하거나, diff에 있는 변경을 빠뜨리지 않는다. 변경 파일 목록과 설명의 파일 집합이 같아야 한다.
- 계획·Issue 범위 밖 변경을 범위 안인 것처럼 묶어 쓰지 않는다. 범위 밖 변경은 따로 적고 사유를 남긴다.
- 설명·코드 블록·로그 인용에 토큰, 키, 접속 문자열, 고객 식별 정보, 내부 예외 스택을 넣지 않는다. 필요하면 파일·줄 번호만 적는다.
- 머지 가능 여부를 단정하지 않는다. 머지는 사람이 결정한다.

## 출력

다음 절을 이 순서로 쓴다. 저장소에 PR template(`.github/pull_request_template.md`)이 있으면 그 헤딩을 우선하고 아래 항목을 그 안에 배치한다.

1. **변경 요약** — 파일별 표: `파일 | 변경 | 근거(Issue AC 번호, 계획 Step, 정책 절)`. `Closes #<n>`은 Issue가 있을 때만.
2. **Acceptance Criteria별 증거** — AC 항목마다 「충족 / 미충족 / 해당 없음」과 근거(테스트 이름, 명령 출력 줄). AC가 없으면 계획의 검증 계약 행을 쓴다.
3. **실행한 검증** — 표: `명령 | 커밋 | 결과 원문(통과 개수·실패 메시지 첫 줄) | 실행자·시각`.
4. **실행하지 않은 검증** — 표: `명령 또는 확인 | 미실행 사유 | 누가 언제 실행해야 하는가`. 없으면 `없음`.
5. **위험과 rollback** — 남은 위험, 영향 범위, 되돌리는 방법(revert 대상 커밋, 데이터 영향 유무). 근거가 부족한 항목은 「미확인」으로 표시하고 무엇을 확인해야 하는지 적는다.
6. **범위 밖·미결** — 계획 밖 변경과 그 사유, 사람 결정이 남은 항목(`notes/pending-decisions.md` 참조), 후속 작업.

## 검증

- 변경 요약의 파일 집합 = `git diff --name-only <base>..<head>` 출력인지 대조한다.
- 「실행한 검증」의 모든 행에 입력으로 받은 출력 원문이 있는지, 「실행하지 않은 검증」에 원문 없는 명령이 전부 들어갔는지 확인한다.
- AC 항목마다 증거가 테스트 이름이나 명령 출력으로 연결되는지, 「잘 동작함」 같은 판정 불가 문장이 없는지 확인한다.
- 본문을 `token|secret|key|password|postgresql://|sk-|re_` 패턴으로 한 번 훑어 매치가 없는지 확인한다(저장소 보안 규칙).
- 사람에게 돌려주는 것: PR 설명 전문, 미확인·미실행 목록. 머지 여부와 추가 검증 실행은 사람이 정한다.
