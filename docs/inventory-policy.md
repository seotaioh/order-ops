# 재고 정책

## 목적과 책임

이 문서는 주문 생성과 결제 과정의 재고 검사 시점, 재고 변경 조건과 재고 부족 차단을 정의한다. 주문 상태의 의미와 전환 허용 여부는 [주문 상태 정책](order-policy.md)이 결정하고, 결제 성공·실패 판정과 결제 응답은 [결제 정책](payment-policy.md)이 결정한다.

## 재고 원칙

- 주문을 저장하기 전에 동일한 `productId`의 주문 수량을 합산하고, 각 상품의 현재 재고가 합산 주문 수량 이상인지 검사한다.
- 상품 하나라도 합산 주문 수량보다 재고가 부족하면 주문을 저장하거나 어떤 상품의 재고도 변경하기 전에 주문 생성을 차단한다.
- 재고가 충분한 주문을 생성해 `pending`으로 저장하는 것만으로는 재고를 차감하지 않는다.
- 결제 성공을 확정하기 직전에 주문의 모든 품목에 대해 현재 재고를 다시 검사한다.
- 결제 성공 조건을 충족한 주문의 재고는 주문 수량만큼 한 번만 차감한다. 같은 주문의 결제 처리로 중복 차감해서는 안 된다.
- 결제가 실패하거나 `payment_failed` 주문의 재결제가 거부되면 재고를 차감하거나 복원하지 않는다.
- 재고 검사와 변경은 주문 전체를 기준으로 적용한다. 일부 품목만 차감한 상태로 주문을 저장하거나 결제를 성공 처리해서는 안 된다.
- 주문 상태 이름과 상태 전환은 주문 상태 정책을 따르며, 결제 API 응답은 결제 정책을 따른다. 재고 정책은 이를 독자적으로 재정의하지 않는다.

## 공유 경계

| 사건 | 이 문서가 판정하는 것 | 다른 정책이 판정하는 것 |
| --- | --- | --- |
| 주문 생성 | 저장 전 재고 충족 여부, 부족 시 미저장·미변경, 생성 시 미차감 | 주문 상태 정책의 유효한 주문 생성 후 `pending` 진입 |
| 결제 성공 | 결제 확정 전 재고 재검사와 주문 수량만큼 한 번의 차감 | 결제 정책의 성공 판정·이력, 주문 상태 정책의 `pending → paid` |
| 결제 실패 | 재고 미차감 | 결제 정책의 402·실패 정보·이력, 주문 상태 정책의 `pending → payment_failed`와 보존 |
| 재결제 거부 | 재고 미차감·미복원 | 결제 정책의 동일 주문 재결제 금지, 주문 상태 정책의 상태 불변 |
| 환불 | 재입고 여부를 아직 판정하지 않음 | 주문 상태 정책의 `paid → refunded`; 결제 정책의 금액 반환 조건 |

이 문서가 주문 상태 정책이나 결제 정책과 같은 사건에 다른 결과를 요구하면 구현 전에 사람에게 확인한다. 결제 결과나 상태 전환 규칙을 이 문서에 복제해 독립적인 규칙으로 만들지 않는다.

## 재고 부족 응답 (2026-10-16 확정)

| 사건 | 응답 | 주문 상태 | 결제 시도 이력 | 재고 |
| --- | --- | --- | --- | --- |
| 주문 생성 시 합산 수량이 재고를 초과 | `409 Conflict`, `{ "message": "Insufficient stock", "productId": "<부족한 상품>" }` | 주문을 저장하지 않음 | 해당 없음 | 변경 없음 |
| 결제 성공 확정 직전 재검사에서 부족 | `409 Conflict`, 같은 본문 | `pending` 유지 | 기록하지 않음 (결제 수단 처리에 진입하지 않았으므로 성공·실패가 판정된 시도가 아님) | 변경 없음 |

`productId`는 부족이 발견된 첫 상품이다. 여러 상품이 부족해도 한 상품만 알리며, 주문 전체를 거부한다.

## 보류 사항

- 환불 완료 후 판매 가능 재고를 복원할지 여부와 복원 시점
- 부분 환불이 도입될 경우 품목별 재고 복원 기준

보류 사항은 별도 승인 전까지 재고를 변경하거나 상태·응답을 추정하는 근거로 사용하지 않는다.
