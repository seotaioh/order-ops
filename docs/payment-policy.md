# 결제 정책

## 목적과 책임

이 문서는 결제 성공·실패의 판정, 결제 시도 이력, 결제 API의 실패 응답과 동일 주문 재결제 경계를 정의한다. 주문 상태의 의미와 전환 허용 여부는 [주문 상태 정책](order-policy.md)이 결정하고, 재고 검사와 변경은 [재고 정책](inventory-policy.md)이 결정한다.

## 결제 원칙

- 결제 처리는 주문 상태 정책에서 결제가 허용된 주문에 대해서만 시작한다.
- 결제 처리 단계에 진입해 성공 또는 실패가 판정된 시도는 시각과 결과를 사후에 확인할 수 있도록 이력으로 보존한다.
- 결제 성공은 결제 수단 처리가 성공하고 재고 정책의 결제 완료 조건까지 충족한 경우에만 확정한다. 이에 따른 주문 상태 전환은 주문 상태 정책을 따른다.
- 결제 실패 시 HTTP 402와 실패 정보를 반환하고 실패 시도 이력을 남긴다. 외부에 제공하는 실패 정보에는 카드 정보, 내부 오류, 예외 메시지와 스택 트레이스를 포함하지 않는다.
- 결제 실패 주문을 삭제하지 않는다. 실패한 주문의 상태와 보존 조건은 주문 상태 정책을 따른다.
- `payment_failed`가 된 동일 주문에는 새 결제를 시도하거나 성공 처리하지 않는다. 거부된 재결제 요청은 기존 주문 상태와 결제 이력을 변경하지 않아야 한다.
- 재고 수량의 검사 시점, 차감 조건과 미차감 조건은 재고 정책을 따른다. 결제 정책은 재고 수량을 독자적으로 정의하지 않는다.

## 동일 주문 재결제 정책의 승격

“`payment_failed` 주문은 같은 주문으로 재결제하지 않는다”는 작업별 결정을 장기 결제 정책으로 승격한다.

이 결정은 사람이 명시적으로 확정했으며, 실패 주문과 실패 이력을 보존하는 원칙 및 재결제 거부 뒤 주문 상태와 재고가 변하지 않아야 한다는 검증 기준에 연결되어 있다. 따라서 후속 작업은 이 정책을 다시 선택하거나 재결제를 묵시적으로 허용해서는 안 된다.

여기서 동일 주문 재결제는 `payment_failed` 상태인 주문 ID에 새 결제를 요청하는 행위를 뜻한다. 네트워크 오류나 인프라 오류 때문에 같은 요청을 다시 전송하는 기술적 재시도의 허용 여부, 식별 방식과 횟수 제한은 이 결정에 포함되지 않는다.

## 공유 경계

| 사건 | 이 문서가 판정하는 것 | 다른 정책이 판정하는 것 |
| --- | --- | --- |
| 결제 성공 | 결제 결과와 성공 시도 이력 | 주문 상태 정책의 `pending → paid`, 재고 정책의 재고 검사·차감 |
| 결제 실패 | HTTP 402, 실패 정보와 실패 시도 이력, 동일 주문 재결제 금지 | 주문 상태 정책의 `pending → payment_failed`와 주문 보존, 재고 정책의 미차감 |
| 재고 부족 | 결제 성공으로 확정하지 않음 | 재고 정책의 부족 판정·미차감, 주문 상태 정책의 상태 처리 |
| 환불 | 금액 반환이 완료되어야 환불 상태 전환의 결제 조건을 충족함 | 주문 상태 정책의 `paid → refunded`; 환불 API와 재고 복원은 현재 구현 범위 밖 |

이 문서가 주문 상태 정책이나 재고 정책과 같은 사건에 다른 결과를 요구하면 구현 전에 사람에게 확인한다. 다른 정책의 원칙을 이 문서에 복제해 독립적인 규칙으로 만들지 않는다.

## 확정된 응답 (2026-10-16)

| 사건 | 응답 | 이력·상태 |
| --- | --- | --- |
| 결제 실패 (결제 수단 거절) | `402 Payment Required`, `{ "ok": false, "orderId", "status": "payment_failed", "failure": { "reason", "amountKrw", "at" } }` | 실패 시도 이력에 `failureReason` 저장. `reason`은 안전한 사유 코드(현재 `card_declined`)만 사용 |
| `payment_failed` 주문 재결제 요청 | `400 Bad Request`, `{ "message": "Order is not payable" }` (결제 가능 상태가 아닌 주문에 쓰던 기존 응답을 그대로 사용) | 상태·이력·재고 변경 없음 |
| 결제 시점 재고 부족 | `409 Conflict`, `{ "message": "Insufficient stock", "productId" }` | 결제 시도 이력을 남기지 않음. 주문은 `pending` 유지. 재고 판정 자체는 [재고 정책](inventory-policy.md)을 따름 |

## 보류 사항

- 네트워크·인프라 수준 재시도의 허용 조건, 식별 방식과 최대 횟수
- 환불 API, 금액 반환 처리 방식과 부분 환불 지원 여부

보류 사항은 별도 승인 전까지 구현하거나 허용된 결제 흐름으로 간주하지 않는다.
